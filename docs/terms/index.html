クラウドの概念

クラウドの利点設計の原則移行の戦略クラウドの経済性

クラウドの利点

  • クラウドコンピューティング

    インターネットを通して、サーバー・ストレージ・データベースなどの IT の資源を、必要なときに必要な分だけ使い、使った分だけ払う仕組み。

  • オンプレミス

    自社の建物やデータセンターにサーバーを置き、機器を買って自分たちで管理する形。クラウドと比べられる。

  • 弾力性

    利用者の増減に合わせて、使う資源を自動で増やしたり減らしたりできる性質。忙しい時間だけサーバーを増やし、空いたら減らせる。

  • スケーラビリティ

    需要が増えたときに、資源を足すことで処理できる量を伸ばせる性質。

  • 高可用性

    一部が壊れてもサービスが止まりにくく、使い続けられる性質。複数のアベイラビリティーゾーンに分けて置くことで高められる。

  • 俊敏性（アジリティ）

    新しいサーバーなどを数分で用意できるため、試す・作り直す・広げるのが速くなること。

  • 従量課金

    使った分だけ料金を払う方式。前もって大きな設備を買う必要がない。

  • 規模の経済

    たくさんの利用者がまとめて使うことで、1人あたりのコストが下がること。AWS は全体の規模を生かして料金を下げられる。

  • グローバル展開

    世界各地のリージョンを使い、数分で海外の利用者の近くにシステムを置けること。

  • 耐障害性

    一部に障害が起きても、システム全体としては動き続けられる性質。

  • ディザスタリカバリ（DR）

    災害や大きな障害のあとに、システムとデータを元に戻すこと。別のリージョンにバックアップや予備のシステムを置いて備える。

設計の原則

  • AWS Well-Architected フレームワーク

    クラウドで良いシステムを作るための考え方をまとめたもの。運用上の優秀性・セキュリティ・信頼性・パフォーマンス効率・コスト最適化・持続可能性の6つの柱からなる。

  • 運用上の優秀性の柱

    Well-Architected の柱の1つ。システムを動かし、監視し、手順を改善し続けること。小さく頻繁に変更し、失敗から学ぶ。

  • セキュリティの柱

    Well-Architected の柱の1つ。データ・システム・資産を守ること。ID の管理、記録、暗号化などを行う。

  • 信頼性の柱

    Well-Architected の柱の1つ。決められた働きを正しく続け、障害から自動で回復できるようにすること。

  • パフォーマンス効率の柱

    Well-Architected の柱の1つ。必要な性能に合わせて資源を効率よく使い、変化に合わせて選び直すこと。

  • コスト最適化の柱

    Well-Architected の柱の1つ。不要な費用を避け、価値に見合った使い方をすること。

  • 持続可能性の柱

    Well-Architected の柱の1つ。使うエネルギーや資源を減らし、環境への影響を小さくすること。6つ目の柱として後から加わった。

  • AWS Well-Architected Tool

    自分のシステムが Well-Architected フレームワークに沿っているかを、質問に答えながら確かめ、改善点を見つけるサービス。

移行の戦略

  • AWS CAF

    クラウド導入フレームワーク。クラウドへの移行を進めるための指針で、ビジネス・人材・ガバナンス・プラットフォーム・セキュリティ・運用の6つの観点で整理する。ビジネスリスクの低減、ESG の向上、収益の増加、運用の効率化などの効果をめざす。

  • リホスト

    今のシステムを、作りをほとんど変えずにクラウドのサーバーへ移す方法。「リフトアンドシフト」とも呼ぶ。

  • リプラットフォーム

    大きく作り直さずに、一部だけクラウド向けに変えて移す方法。例: 自分で管理していたデータベースを Amazon RDS に移す。

  • リファクタリング

    クラウドの機能を生かすように、アプリの作りを大きく作り直して移す方法。リアーキテクトとも呼ぶ。

  • 再購入（リパーチェス）

    今のソフトウェアをやめて、SaaS などの別の製品に乗り換える方法。

  • 保持（リテイン）

    今は移さず、手元にそのまま残しておく判断。

  • 廃止（リタイア）

    もう使っていないシステムを、移さずに止めること。

  • 再配置（リロケート）

    VMware などの仮想化の環境を、作りを変えずにまとめてクラウドへ移す方法。

クラウドの経済性

  • 固定費

    使った量にかかわらず、決まってかかる費用。オンプレミスでは、サーバーの購入などの大きな固定費が先にかかる。

  • 変動費

    使った量に応じて変わる費用。クラウドでは、先払いの固定費を変動費に置き換えられる。

  • CapEx（設備投資）

    サーバーや建物など、長く使う設備を先にまとめて買う支出。

  • OpEx（運用費）

    日々の運用で、使った分を払っていく支出。クラウドの利用料はこちらにあたる。

  • TCO（総保有コスト）

    機器の購入だけでなく、電気代・場所代・保守・人件費まで含めた全体の費用。クラウドとオンプレミスを比べるときに使う。

  • BYOL

    すでに持っているソフトウェアのライセンスを、クラウドでもそのまま使う方式。

  • ライセンス込みの料金

    ソフトウェアのライセンス代が、AWS の利用料金に含まれている方式。ライセンスを持っていなくてもすぐ使える。BYOL と比べて選ぶ。

  • 適切なサイジング（ライトサイジング）

    実際の使われ方に合わせて、サーバーなどの大きさを見直し、むだな費用を減らすこと。

  • 自動化

    手作業を仕組みに置き換えること。クラウドでは、サーバーの準備や増減を自動にでき、手間とミスを減らせる。

セキュリティとコンプライアンス

責任共有モデルアクセス管理保護と検知ガバナンスとコンプライアンス

責任共有モデル

  • 責任共有モデル

    セキュリティの責任を AWS と利用者で分ける考え方。AWS は「クラウドのセキュリティ」、利用者は「クラウドにおけるセキュリティ」を受け持つ。

  • クラウドのセキュリティ

    責任共有モデルで AWS が受け持つ範囲。データセンターの建物・機器・ネットワーク・仮想化の仕組みなど、サービスを動かす土台を守る。

  • クラウドにおけるセキュリティ

    責任共有モデルで利用者が受け持つ範囲。データ、アクセスの設定、ファイアウォールの設定、暗号化、EC2 なら OS の更新など。

  • 共通の統制

    AWS と利用者の両方が、それぞれの範囲で行う管理。パッチの管理・設定の管理・セキュリティの教育など。

  • サービスによる責任の違い

    利用者の責任の範囲は、使うサービスで変わること。EC2 では OS の更新も利用者の責任だが、RDS や Lambda では OS の管理を AWS が受け持つ。

アクセス管理

  • AWS IAM

    だれが、どの AWS のサービスや資源を使えるかを管理するサービス。ユーザー・グループ・ロール・ポリシーを使う。追加料金はかからない。

  • ルートユーザー

    AWS アカウントを作ったときのメールアドレスでログインする、すべての権限を持つユーザー。ふだんの作業には使わず、MFA を設定して守る。

  • ルートユーザーだけの作業

    アカウントの設定の変更や、アカウントの解約など、ルートユーザーでしかできない一部の作業。

  • IAM ユーザー

    AWS を使う人やアプリごとに作る ID。パスワードやアクセスキーを持てる。

  • IAM グループ

    IAM ユーザーをまとめたもの。グループに権限を付けると、入っている全員に同じ権限が付く。

  • IAM ロール

    一時的に権限を借りるための ID。EC2 などのサービスや、別のアカウントの利用者に、決まった権限を一時的に渡すときに使う。

  • IAM ポリシー

    「何に対して、何をしてよいか（してはいけないか）」を JSON で書いた権限の決まり。ユーザー・グループ・ロールに付ける。

  • AWS 管理ポリシー

    AWS があらかじめ用意している IAM ポリシー。よくある使い方の権限を、すぐに付けられる。

  • カスタマー管理ポリシー

    利用者が自分で書いて管理する IAM ポリシー。必要な権限だけに細かく絞れる。

  • 最小権限の原則

    仕事に必要な、最小限の権限だけを与える考え方。間違いや乗っ取りがあったときの被害を小さくできる。

  • MFA

    多要素認証。パスワードに加えて、スマホのアプリなどが出す1回だけの番号でも本人を確かめる方法。ルートユーザーには必ず設定する。

  • アクセスキー

    プログラムや CLI から AWS を使うための、アクセスキー ID とシークレットアクセスキーの組。人に見せたり、コードに書いたりしない。

  • パスワードポリシー

    IAM ユーザーのパスワードの長さ・使う文字の種類・有効期限などの決まり。

  • AWS IAM Identity Center

    複数の AWS アカウントや業務アプリへのログインを、1か所でまとめて管理するサービス。1回のログインで使える（シングルサインオン）。

  • ID フェデレーション

    会社の ID などの外部の ID を使って、AWS にログインできるようにする仕組み。AWS の中に別のユーザーを作らなくてよい。

  • クロスアカウント IAM ロール

    別の AWS アカウントの利用者が、ロールを引き受けて一時的に権限を使えるようにする仕組み。

  • Amazon Cognito

    Web やスマホのアプリに、会員登録とログインの機能を付けるサービス。

  • AWS Directory Service

    Microsoft Active Directory を、AWS の中で使えるようにするサービス。

  • AWS Secrets Manager

    データベースのパスワードや API キーなどの秘密の情報を安全に保管し、定期的に自動で切り替える（ローテーション）サービス。

  • AWS RAM

    サブネットなどの資源を、ほかの AWS アカウントと共有するサービス。

  • SCP（サービスコントロールポリシー）

    AWS Organizations で、メンバーのアカウントが使える権限の上限を決めるポリシー。

保護と検知

  • AWS WAF

    Web アプリへの攻撃（SQL インジェクションなど）を、ルールで見分けて止めるファイアウォール。CloudFront などと組み合わせて使う。

  • AWS Shield

    DDoS 攻撃からシステムを守るサービス。Standard は追加料金なしで自動で使え、Advanced は有料で、より高度な保護と専門チームの支援がある。

  • DDoS 攻撃

    たくさんのコンピュータから大量の通信を送りつけて、サービスを使えなくする攻撃。

  • AWS Firewall Manager

    複数のアカウントの WAF や Shield などのルールを、まとめて設定・管理するサービス。

  • Amazon GuardDuty

    ログを機械学習などで分析し、不正なアクセスやあやしい動きを見つけて知らせるサービス。

  • Amazon Inspector

    EC2・コンテナのイメージ・Lambda の関数に、ソフトウェアの脆弱性や意図しないネットワークへの公開がないかを、自動で調べるサービス。

  • Amazon Macie

    S3 に保存されたデータの中から、個人情報などの大事なデータを機械学習で見つけて知らせるサービス。

  • Amazon Detective

    セキュリティの問題が見つかったときに、ログをもとに原因や影響の範囲を調べるのを助けるサービス。

  • AWS Security Hub

    GuardDuty・Inspector・Macie などの結果を1か所に集め、セキュリティの状態をまとめて確かめるサービス。

  • AWS KMS

    データを暗号化するための鍵を作って管理するサービス。多くの AWS のサービスの暗号化と連携する。

  • AWS CloudHSM

    専用のハードウェア（HSM）で、暗号化の鍵を管理するサービス。鍵を自分だけで管理しなければならないときに使う。

  • AWS Certificate Manager（ACM）

    Web サイトの通信を暗号化する SSL/TLS 証明書を発行・更新するサービス。ロードバランサーや CloudFront と組み合わせる公開証明書は、追加料金なしで使える。

  • 保存時の暗号化

    ディスクやデータベースに保存しているデータを暗号化すること。S3・EBS・RDS などで使える。

  • 転送中の暗号化

    ネットワークを流れているデータを、TLS などで暗号化すること。

ガバナンスとコンプライアンス

  • AWS Artifact

    AWS のセキュリティやコンプライアンスの報告書（第三者による監査のレポートなど）や契約書を、ダウンロードできるサービス。

  • AWS CloudTrail

    AWS アカウントでの操作（だれが、いつ、何をしたか）を記録するサービス。監査や調査に使う。

  • AWS Config

    AWS の資源の設定を記録し、決めたルールに合っているかを確かめ続けるサービス。設定が変わった履歴も見られる。

  • コンプライアンス

    法律・業界の基準・社内の決まりを守ること。AWS は多くの基準の認証を受けているが、利用者のシステムが基準に合うようにするのは利用者の責任でもある。

  • AWS コンプライアンスプログラム

    AWS が取得している認証や、準拠している基準（ISO 27001・PCI DSS・SOC など）の情報。国や業界ごとの要件を調べるときに使う。

  • IAM 認証情報レポート

    アカウントのすべての IAM ユーザーと、パスワード・アクセスキー・MFA の状態を一覧にしたレポート。監査に使う。

  • AWS Trust and Safety チーム

    AWS の資源が、迷惑メールの送信や攻撃などの悪用に使われているときに、報告を受け付けるチーム。

  • AWS セキュリティセンター

    AWS のセキュリティへの取り組みや、ベストプラクティス、お知らせをまとめた Web ページ。

  • AWS セキュリティブログ

    AWS のセキュリティの新しい機能や、使い方を紹介するブログ。

使い方と導入

  • AWS マネジメントコンソール

    Web ブラウザの画面から AWS のサービスを操作する方法。初めての作業や、1回だけの作業に向く。

  • AWS CLI

    コマンドを入力して AWS を操作する道具。同じ手順を繰り返したり、自動にしたりしやすい。

  • AWS SDK

    プログラムから AWS を操作するための部品集。Python・Java など多くの言語向けがある。

  • API

    プログラムどうしがやり取りするための窓口。AWS のすべての操作は API を通して行われる。

  • IaC

    サーバーやネットワークなどの構成をコード（テンプレート）で書き、同じ環境を何度でも正確に作れるようにすること。

  • AWS CloudFormation

    テンプレートに書いた構成どおりに、AWS の資源をまとめて作ったり消したりするサービス。IaC を実現する。

  • クラウドデプロイメント

    システムのすべてをクラウドの上で動かす形。

  • ハイブリッドデプロイメント

    社内のシステム（オンプレミス）とクラウドをつないで、一緒に使う形。

  • オンプレミスデプロイメント

    自社の設備の中に、仮想化などでクラウドのような環境を作って使う形。プライベートクラウドとも呼ぶ。

  • AWS Elastic Beanstalk

    アプリのコードを上げるだけで、サーバー・ロードバランサー・Auto Scaling などの環境を自動で用意してくれるサービス。

  • AWS Systems Manager

    たくさんのサーバーの更新（パッチ）・設定・コマンドの実行をまとめて管理するサービス。Parameter Store で、設定の値や秘密の情報も保管できる。

グローバルインフラ

  • リージョン

    AWS のデータセンターが集まっている、世界の地域。データを置く国の決まり・利用者への近さ・料金・使えるサービスで選ぶ。

  • アベイラビリティーゾーン（AZ）

    1つのリージョンの中にある、独立したデータセンターの集まり。電源やネットワークを別にしていて、同時に止まりにくい。複数の AZ に分けて置くと高可用性になる。

  • エッジロケーション

    利用者の近くに置かれた拠点。CloudFront などがデータを一時的に保存（キャッシュ）して、速く届けるのに使う。

  • データ主権

    データを、決まった国や地域の法律の下に置かなければならないという考え。データを置くリージョンを選んで対応する。

  • 複数リージョンの利用

    複数のリージョンにシステムを置くこと。災害対策、事業の継続、遠くの利用者への速さ、データ主権などのために使う。

  • 単一障害点

    そこが壊れるとシステム全体が止まってしまう部分。アベイラビリティーゾーンどうしは、単一障害点を共有しないように作られている。

  • AWS Outposts

    AWS と同じ機器とサービスを、自社のデータセンターなどに置いて使えるようにするサービス。ハイブリッドで使う。

コンピューティング

  • Amazon EC2

    クラウド上の仮想サーバー。OS と大きさ（インスタンスタイプ）を選んで、数分で起動できる。

  • インスタンスタイプ

    EC2 の大きさや性能の種類。CPU・メモリ・ストレージ・ネットワークの組み合わせで分かれる。

  • 汎用インスタンス

    CPU・メモリ・ネットワークのバランスがとれた EC2 のインスタンス。Web サーバーなどに向く。

  • コンピューティング最適化インスタンス

    CPU の性能が高い EC2 のインスタンス。大量の計算や、動画の変換などに向く。

  • メモリ最適化インスタンス

    メモリを多く持つ EC2 のインスタンス。大きなデータをメモリの上で処理するデータベースなどに向く。

  • ストレージ最適化インスタンス

    手元のストレージへの読み書きがとても速い EC2 のインスタンス。大量のデータを高速に読み書きする処理に向く。

  • 高速コンピューティングインスタンス

    GPU などの専用のハードウェアを持つ EC2 のインスタンス。機械学習や画像の処理に向く。

  • AMI

    EC2 を起動するためのひな形。OS や、入れておくソフトウェアを含む。

  • AWS Auto Scaling

    利用の状況に合わせて、EC2 などの数を自動で増やしたり減らしたりするサービス。弾力性を実現する。

  • Elastic Load Balancing（ELB）

    届いた通信を、複数の EC2 などに振り分けるサービス（ロードバランサー）。負荷を分け、壊れたサーバーを外して高可用性を保つ。

  • AWS Lambda

    サーバーを用意せずに、プログラム（関数）を動かせるサービス。イベントが起きたときだけ動き、動いた時間の分だけ払う。

  • サーバーレス

    サーバーの準備や管理を、利用者がしなくてよい使い方。AWS Lambda や AWS Fargate など。

  • AWS Fargate

    コンテナを、サーバーを管理せずに動かせるサービス。ECS や EKS と組み合わせて使う。

  • コンテナ

    アプリと、動かすのに必要なものをひとまとめにした箱。どこでも同じように動かせる。

  • Amazon ECS

    コンテナを動かして管理する、AWS のサービス。

  • Amazon EKS

    Kubernetes を使ってコンテナを動かすためのサービス。

  • Amazon ECR

    コンテナのイメージを保管する場所（レジストリ）。

  • Amazon Lightsail

    サーバー・ストレージ・ネットワークなどがセットになった、月額の定額で使いやすいサービス。小さな Web サイトなどに向く。

  • AWS Batch

    大量の計算の仕事（バッチ処理）を、必要な数のサーバーを自動で用意して実行するサービス。

データベース

  • Amazon RDS

    MySQL・PostgreSQL などのリレーショナルデータベースを、AWS が管理してくれるサービス。バックアップや更新を自動にできる。

  • Amazon Aurora

    AWS がクラウド向けに作った、MySQL・PostgreSQL と互換のあるリレーショナルデータベース。性能と可用性が高い。

  • Amazon DynamoDB

    キーと値で読み書きする NoSQL のデータベース。サーバーの管理がいらず、大量のアクセスでも速く応える。

  • Amazon ElastiCache

    データをメモリに置いて、とても速く読み出せるようにするサービス（キャッシュ）。Redis や Memcached と互換がある。

  • Amazon Neptune

    人と人のつながりのような「関係」のデータを扱う、グラフデータベースのサービス。

  • Amazon DocumentDB

    JSON のようなドキュメントの形のデータを扱うデータベース。MongoDB と互換がある。

  • リレーショナルデータベース

    表（テーブル）の形でデータを持ち、SQL で操作するデータベース。

  • NoSQL データベース

    表の形にとらわれず、キーと値やドキュメントなどの形でデータを持つデータベース。大量のデータを速く扱うのに向く。

  • マネージドサービス

    サーバーの準備・更新・バックアップなどの手間を、AWS が受け持つサービス。例えば RDS は、EC2 に自分でデータベースを入れるより管理が楽になる。

  • AWS DMS

    データベースを、止める時間を短くしながら AWS へ移すサービス。

  • AWS SCT

    種類の違うデータベースへ移すときに、テーブルの定義などを変換する道具。

ネットワーク

  • Amazon VPC

    AWS の中に作る、自分専用の仮想のネットワーク。IP アドレスの範囲やサブネットを自分で決める。

  • サブネット

    VPC の中を、さらに分けたネットワーク。1つのアベイラビリティーゾーンの中に作る。

  • パブリックサブネット

    インターネットと直接やり取りできるサブネット。Web サーバーなどを置く。

  • プライベートサブネット

    インターネットから直接はつながらないサブネット。データベースなどを置く。

  • インターネットゲートウェイ

    VPC とインターネットをつなぐ出入口。

  • NAT ゲートウェイ

    プライベートサブネットのサーバーが、外から入られずにインターネットへ出ていけるようにする仕組み。

  • セキュリティグループ

    EC2 などに付ける仮想のファイアウォール。許可する通信だけを決める。行きの通信を許すと、戻りの通信も自動で許される（ステートフル）。

  • ネットワーク ACL

    サブネットの単位で付けるファイアウォール。許可と拒否の両方のルールを書け、行きと戻りの通信を別々に決める（ステートレス）。

  • Amazon Route 53

    AWS の DNS のサービス。ドメイン名の登録、名前から IP アドレスへの変換、通信の振り分けを行う。

  • Amazon CloudFront

    世界のエッジロケーションを使って、Web サイトや動画などを利用者の近くから速く届けるサービス（CDN）。

  • AWS Direct Connect

    自社のデータセンターと AWS を、インターネットを通らない専用の線でつなぐサービス。通信が安定していて速い。

  • AWS VPN

    インターネットを通して、暗号化した通信で安全に AWS とつなぐサービス。Site-to-Site VPN と Client VPN がある。

  • AWS Site-to-Site VPN

    会社のネットワークと VPC を、インターネットを通る暗号化した通信でつなぐサービス。

  • AWS Client VPN

    社員の PC などから、VPN で AWS や社内のネットワークに安全につなぐサービス。

  • AWS Transit Gateway

    たくさんの VPC と社内のネットワークを、真ん中の1か所でまとめてつなぐサービス。

  • AWS PrivateLink

    インターネットを通さずに、VPC から AWS のサービスや他社のサービスへ非公開でつなぐ仕組み。

  • AWS Global Accelerator

    AWS の世界のネットワークを使って、利用者からアプリまでの通信の速さと安定性を高めるサービス。

  • Amazon API Gateway

    API を作って公開し、管理するサービス。Lambda と組み合わせて、サーバーレスの API を作れる。

ストレージ

  • オブジェクトストレージ

    ファイルを「オブジェクト」として、名前（キー）を付けて保存する形。容量の上限を気にせず、大量に置ける。Amazon S3 が代表。

  • ブロックストレージ

    データを小さなブロックに分けて保存する形。サーバーにつなぐディスクとして使う。Amazon EBS が代表。

  • ファイルストレージ

    フォルダとファイルの形で保存し、複数のサーバーから同時に使える形。Amazon EFS や Amazon FSx。

  • Amazon S3

    容量の上限なくファイルを保存できる、オブジェクトストレージのサービス。データを複数の場所に保存していて、耐久性がとても高い。

  • バケット

    S3 でオブジェクトを入れる入れ物。名前は世界中でほかと重ならないように付ける。

  • S3 ストレージクラス

    S3 の保存の種類。どれくらいよく使うか、どれくらい速く取り出す必要があるかで選び、料金を下げる。

  • S3 Standard

    よく使うデータ向けの、標準の S3 のストレージクラス。

  • S3 Intelligent-Tiering

    使われ方に合わせて、データを自動で安いクラスへ移す S3 のストレージクラス。使われ方がわからないデータに向く。

  • S3 Standard-IA

    あまり使わないが、必要なときはすぐ取り出したいデータ向けの S3 のストレージクラス。保存は安いが、取り出すときに料金がかかる。

  • S3 One Zone-IA

    1つのアベイラビリティーゾーンだけに保存する、あまり使わないデータ向けのクラス。安いが、その AZ が壊れると失われることがあるので、作り直せるデータに使う。

  • Amazon S3 Glacier

    長く保存しておく（アーカイブ）データ向けの、とても安い S3 のストレージクラスの仲間。Instant Retrieval・Flexible Retrieval・Deep Archive があり、取り出しの速さと料金が違う。

  • S3 Glacier Deep Archive

    S3 でいちばん安いストレージクラス。取り出しには時間がかかる。何年も保存しておく記録向け。

  • S3 ライフサイクルポリシー

    日数などの決まりに合わせて、S3 のデータを安いクラスへ自動で移したり、消したりする設定。

  • Amazon EBS

    EC2 につないで使うブロックストレージ（ディスク）。EC2 を止めてもデータは残る。スナップショットでバックアップできる。

  • インスタンスストア

    EC2 の機器に直接ついている一時的なディスク。速いが、インスタンスを止めるとデータが消える。

  • EBS スナップショット

    EBS のある時点の状態を保存したバックアップ。

  • Amazon EFS

    複数の EC2 から同時に使える、容量が自動で増えるファイルストレージ。

  • Amazon FSx

    Windows File Server や Lustre など、よく使われるファイルシステムを、AWS が管理して提供するサービス。

  • AWS Storage Gateway

    社内のシステムと AWS のストレージをつなぎ、よく使うデータは手元に置き（キャッシュ）ながら、AWS に保存するサービス。ハイブリッドで使う。

  • AWS Backup

    多くの AWS のサービスのバックアップを、1か所でまとめて設定・管理するサービス。

  • AWS Elastic Disaster Recovery

    サーバーを AWS に常に複製しておき、災害のときに AWS の上ですぐに立ち上げ直せるようにするサービス。

AIと分析

  • Amazon SageMaker AI

    機械学習のモデルを作る・学習させる・使えるようにする（デプロイ）までを、まとめて行うサービス。

  • Amazon Lex

    声や文字で会話するチャットボットを作るサービス。

  • Amazon Polly

    文章を、自然な声で読み上げる（音声合成）サービス。

  • Amazon Transcribe

    話した声を、文字に起こすサービス。

  • Amazon Translate

    文章を、別の言語に翻訳するサービス。

  • Amazon Comprehend

    文章から、気持ち（よい・悪い）やキーワードなどを読み取る、自然言語処理のサービス。

  • Amazon Rekognition

    画像や動画から、物・人の顔・文字などを見分けるサービス。

  • Amazon Textract

    書類をスキャンした画像から、文字や表のデータを取り出すサービス。

  • Amazon Q

    生成 AI のアシスタント。仕事の質問に答えたり、プログラムを書くのを手伝ったりする。

  • Amazon Athena

    S3 に置いたデータを、そのまま SQL で調べられるサービス。サーバーの準備がいらない。

  • Amazon Redshift

    大量のデータを集めて分析するための、データウェアハウスのサービス。

  • Amazon EMR

    Apache Spark や Hadoop などを使って、大量のデータを処理するサービス。

  • AWS Glue

    データを集めて、分析しやすい形に変換する（ETL）サービス。データの目録（カタログ）も作る。

  • Amazon Kinesis

    動画やセンサーのデータなどを、流れてくるそばから（リアルタイムに）集めて処理するサービス。

  • Amazon OpenSearch Service

    大量のデータやログを検索・分析し、見える化するサービス。

  • Amazon Quick Sight

    データをグラフやダッシュボードにして見える化する、BI のサービス。

そのほかのサービス

  • Amazon EventBridge

    アプリや AWS のサービスで起きた出来事（イベント）を受けて、決めた処理につなぐサービス。決まった時刻に処理を動かすこともできる。

  • Amazon SNS

    メッセージを、メール・SMS・アプリなど多くの受け取り先へ一斉に送る（通知する）サービス。

  • Amazon SQS

    メッセージを順番待ちの列（キュー）にためて、アプリどうしを切り離してやり取りさせるサービス。

  • AWS Step Functions

    複数のサービスの処理の流れ（ワークフロー）を、図のように組み立てて自動で動かすサービス。

  • Amazon Connect

    クラウドで使える、コールセンター（コンタクトセンター）のサービス。

  • Amazon SES

    お知らせや案内のメールを、大量に送るサービス。

  • AWS CodeBuild

    プログラムのコードをビルドして、テストまで自動で行うサービス。

  • AWS CodePipeline

    コードの変更から、ビルド・テスト・デプロイまでの流れを自動にするサービス。

  • AWS X-Ray

    アプリの中で、処理がどこを通り、どこで時間がかかったりエラーになったりしているかを追いかけるサービス。

  • Amazon WorkSpaces

    クラウドの上の仮想のデスクトップ（Windows など）を、PC やタブレットから使えるサービス。

  • Amazon AppStream 2.0

    アプリをクラウドで動かし、その画面をブラウザに届けて使えるようにするサービス。

  • Amazon WorkSpaces Secure Browser

    社内の Web サイトなどに、安全なブラウザを通してアクセスできるようにするサービス。

  • AWS Amplify

    Web やスマホのアプリの画面側（フロントエンド）と裏側の仕組みを、すばやく作って公開できるサービス。

  • AWS IoT Core

    センサーや家電などの IoT 機器を、安全に AWS につないでデータをやり取りするサービス。

運用と監視

  • Amazon CloudWatch

    AWS の資源やアプリの状態（CPU の使用率など）とログを集めて監視し、決めた値を超えたら知らせる（アラーム）サービス。

  • AWS Compute Optimizer

    使われ方を分析して、EC2 などのちょうどよい大きさを提案するサービス。

  • AWS Control Tower

    複数の AWS アカウントの環境を、決まった安全なルールですばやく用意し、管理するサービス。

  • AWS Service Catalog

    会社で使ってよいと認めた AWS の構成をカタログにして、社員が選んで使えるようにするサービス。

  • Service Quotas

    AWS のサービスごとの上限（クォータ）を確かめ、引き上げを申し込むサービス。

  • AWS License Manager

    ソフトウェアのライセンスの使用数を管理し、使いすぎを防ぐサービス。

移行のサービス

  • AWS Application Migration Service

    サーバーを、作りを変えずに（リホスト）AWS へ移すサービス。

  • AWS Application Discovery Service

    社内のサーバーの構成や使われ方を調べて、移行の計画に役立てるサービス。

  • AWS Migration Hub

    移行の進み具合を、1か所でまとめて確かめるサービス。

  • Migration Evaluator

    今のシステムを AWS に移した場合の費用を見積もり、移行を決める材料にするサービス。

料金モデル

  • オンデマンドインスタンス

    前もって約束せず、使った時間の分だけ払う EC2 の買い方。急な仕事や、短い期間の利用に向く。

  • リザーブドインスタンス（RI）

    1年か3年の利用を約束することで、オンデマンドより大きく割引される EC2 などの買い方。ずっと動かしておくシステムに向く。

  • リザーブドインスタンスの柔軟性

    スタンダードとコンバーティブルがあり、コンバーティブルは期間の途中でインスタンスのタイプを変えられる。リージョン単位のリザーブドインスタンスは、同じファミリーの別の大きさにも割引が当たる。

  • スポットインスタンス

    AWS の余っている EC2 を、大きな割引で使える買い方。AWS が必要になると中断されることがあるので、止まってもよい処理に向く。

  • Savings Plans

    1年か3年、1時間あたりの利用額を約束することで割引される料金のプラン。インスタンスのタイプを変えても当てはまり、Lambda や Fargate にも使える種類がある。

  • Dedicated Instances

    ほかの利用者と共有しない、専用のハードウェアの上で動く EC2 のインスタンス。ハードウェア専有インスタンスとも呼ぶ。

  • Dedicated Hosts

    物理サーバー1台を、まるごと自分専用にする仕組み。サーバー単位のソフトウェアのライセンス（BYOL）を使いたいときに向く。

  • オンデマンドキャパシティ予約

    特定のアベイラビリティーゾーンで、EC2 を必要なときに確実に起動できるよう、容量を前もって確保する仕組み。期間の約束はいらないが、使わなくても料金がかかる。

  • データ転送の料金

    インターネットから AWS に入るデータは基本的に無料で、AWS から外へ出るデータには料金がかかる。リージョンの間や、アベイラビリティーゾーンの間の転送にも料金がかかることがある。

  • AWS 無料利用枠

    決まった範囲なら、無料で AWS のサービスを試せる仕組み。内容や期間は、サービスや時期によって違う。

コスト管理

  • AWS Budgets

    予算を決めて、使った額や、この先の予測が予算を超えそうなときに知らせるサービス。

  • AWS Cost Explorer

    これまでの料金の使い方をグラフで見て分析し、この先の予測もできる道具。

  • AWS Pricing Calculator

    AWS を使う前に、構成を入力して月の料金を見積もる道具。

  • AWS Cost and Usage Reports

    料金と使用量の、いちばん細かいデータを出すレポート。S3 に保存して分析する。

  • コスト配分タグ

    資源に付けた「タグ」（部署名やプロジェクト名など）ごとに、料金を分けて集計する仕組み。AWS が作るタグと、利用者が作るタグがある。

  • AWS Organizations

    複数の AWS アカウントをまとめて管理するサービス。請求を1つにまとめたり（一括請求）、使ってよいサービスを決めたりできる。

  • 一括請求

    AWS Organizations で、複数のアカウントの請求を1つにまとめる機能。使用量が合計されるので数量割引を受けやすく、リザーブドインスタンスなどの割引もアカウントの間で共有できる。

  • AWS Marketplace

    他社のソフトウェアやサービスを探し、AWS の請求とまとめて買えるオンラインのカタログ。セキュリティの製品も多い。

サポートと情報源

  • AWS サポートプラン

    AWS への技術的な問い合わせの手厚さで選ぶプラン。無料のベーシックサポートと、有料の Business Support+・Enterprise Support・Unified Operations がある。

  • ベーシックサポート

    すべての AWS アカウントに無料で付くサポート。請求やアカウントの問い合わせ、ドキュメント、re:Post、Trusted Advisor の基本の点検などが使える。

  • AWS Business Support+

    有料のサポートプランの入門。技術的な問い合わせができ、AI による支援も使える。それまでの Developer Support と Business Support に代わるプランとして始まった。

  • AWS Enterprise Support

    大事なシステムを動かす企業向けの、手厚い有料のサポート。担当のテクニカルアカウントマネージャー（TAM）が付き、運用を一緒に見直す。

  • AWS Unified Operations

    いちばん手厚い有料のサポート。重大な障害にとても速く対応する、専任のチームが付く。

  • TAM（テクニカルアカウントマネージャー）

    Enterprise Support などで付く、担当の技術者。システムの運用や改善について、続けて助言する。

  • AWS Support Center

    サポートへの問い合わせ（ケース）を作って、やり取りする画面。

  • AWS re:Post

    AWS についての質問と回答を、利用者どうしや専門家とやり取りするコミュニティのサイト。

  • AWS Knowledge Center

    AWS についてよくある質問と、その答えをまとめたページ。

  • AWS Prescriptive Guidance

    移行や設計のための、具体的な手順や型（パターン）をまとめた AWS の資料集。

  • AWS ホワイトペーパー

    AWS の考え方や、設計のベストプラクティスをくわしく説明した、AWS が出している文書。

  • AWS Trusted Advisor

    アカウントを自動で点検し、コストの節約・性能・セキュリティ・耐障害性・サービスの上限などについて、改善のアドバイスを出すサービス。

  • AWS Health Dashboard

    AWS のサービスの障害や、自分のアカウントに関わる予定の作業などのお知らせを確かめる画面。同じ情報を、プログラムから AWS Health API で取り出せる。

パートナーと専門家

  • AWS Professional Services

    AWS の専門家のチームが、移行や大きなプロジェクトを手伝う有料のサービス。

  • AWS ソリューションアーキテクト

    AWS の技術の専門家。利用者に合うシステムの設計を一緒に考え、助言する。

  • APN（AWS パートナーネットワーク）

    AWS を使った製品やサービスを提供する会社の集まり。パートナーは研修・認定・イベント・割引などの支援を受けられる。

  • ISV

    自社でソフトウェアの製品を作って売る会社。AWS Marketplace で製品を出していることも多い。

  • システムインテグレーター（SI）

    利用者に合わせて、システムの設計・構築・運用を請け負う会社。AWS のパートナーとして、移行などを手伝う。
