RDS と Aurora と DynamoDB の違い

RDS は MySQL などのリレーショナルデータベースを AWS が管理してくれるサービス、Aurora は AWS がクラウド向けに作った高性能なリレーショナルデータベース、DynamoDB はキーと値で読み書きする NoSQL のデータベースです。

表で比べる

観点Amazon RDSAmazon AuroraAmazon DynamoDB
データベースの種類リレーショナル（表の形・SQL）リレーショナル（表の形・SQL）NoSQL（キーと値・ドキュメント）
中身MySQL・PostgreSQL・Oracle・SQL Server などのエンジンを選ぶMySQL・PostgreSQL と互換のある、AWS が作ったエンジンAWS が作った NoSQL のデータベース
サーバーの管理インスタンスの大きさを選ぶ。更新やバックアップは AWS が自動でできるRDS の仲間として管理されるサーバーの管理がいらない（サーバーレス）
向いている用途今の業務システムのデータベースをそのまま移す高い性能と可用性が必要なリレーショナルデータベース大量のアクセスに、とても速く応える必要があるアプリ

見分けるポイント

  • 「SQL」「表」「今使っている MySQL や Oracle」なら RDS
  • 「MySQL・PostgreSQL と互換」「高性能」「AWS がクラウド向けに作った」なら Aurora
  • 「NoSQL」「キーと値」「サーバーレス」「ミリ秒単位の速さ」なら DynamoDB
  • EC2 に自分でデータベースを入れると、OS やデータベースの更新は利用者の仕事。RDS などのマネージドサービスなら AWS が受け持つ

試験での出され方

「スキーマが決まっていないデータを、サーバーを管理せずに速く扱いたい」なら DynamoDB、「オンプレミスの MySQL を、管理の手間を減らして移したい」なら RDS（または Aurora）のように、データの形と管理の手間で選ぶ問題がよく出ます。

それぞれの用語

  • Amazon RDS

    MySQL・PostgreSQL などのリレーショナルデータベースを、AWS が管理してくれるサービス。バックアップや更新を自動にできる。

  • Amazon Aurora

    AWS がクラウド向けに作った、MySQL・PostgreSQL と互換のあるリレーショナルデータベース。性能と可用性が高い。

  • Amazon DynamoDB

    キーと値で読み書きする NoSQL のデータベース。サーバーの管理がいらず、大量のアクセスでも速く応える。
