IAM ユーザーと IAM グループと IAM ロールの違い

IAM ユーザーは人やアプリごとの ID、IAM グループはユーザーをまとめて同じ権限を付けるための入れ物、IAM ロールは一時的に権限を借りるための ID です。権限そのものは IAM ポリシーで決めます。

表で比べる

観点IAM ユーザーIAM グループIAM ロール
何か人やアプリごとに作る IDIAM ユーザーをまとめたもの一時的に引き受けて使う ID
認証情報パスワードやアクセスキーを持てる（長く使う）持たない（ログインできない）一時的な認証情報が自動で発行される
使う人・もの決まった1人（1つのアプリ）グループに入っている全員EC2 などの AWS のサービス、別のアカウントの利用者、外部の ID でログインした人
よくある使い方社員1人ごとに作る「開発者」「管理者」など役割ごとにまとめて権限を付けるEC2 上のアプリに S3 を読む権限を渡す

見分けるポイント

  • 「一時的な」「EC2 にアクセス権を与える」「別のアカウント」が出てきたら IAM ロール
  • 「同じ権限をまとめて付ける」ならIAM グループ
  • EC2 のアプリにアクセスキーを書き込むより、IAM ロールを付けるほうが安全
  • 権限の中身は IAM ポリシー（JSON）で書き、ユーザー・グループ・ロールに付ける

試験での出され方

「EC2 インスタンス上のアプリケーションに、S3 へのアクセス権を最も安全に与える方法はどれか」（答えは IAM ロール）は定番の問題です。アクセスキーをコードやサーバーに置く選択肢は、まず疑いましょう。

それぞれの用語

  • IAM ユーザー

    AWS を使う人やアプリごとに作る ID。パスワードやアクセスキーを持てる。

  • IAM グループ

    IAM ユーザーをまとめたもの。グループに権限を付けると、入っている全員に同じ権限が付く。

  • IAM ロール

    一時的に権限を借りるための ID。EC2 などのサービスや、別のアカウントの利用者に、決まった権限を一時的に渡すときに使う。
