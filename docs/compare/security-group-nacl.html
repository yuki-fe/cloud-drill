セキュリティグループとネットワーク ACL の違い

どちらも VPC の中で通信を通すか決めるファイアウォールです。セキュリティグループは EC2 などの1台ごと（インスタンス単位）、ネットワーク ACL はサブネットごとに付けます。

表で比べる

観点セキュリティグループネットワーク ACL
付ける場所EC2 などのインスタンス（インスタンス単位）サブネット（サブネット単位）
書けるルール許可だけ許可と拒否の両方
戻りの通信行きを許可すれば、戻りも自動で許可（ステートフル）行きと戻りを別々に決める（ステートレス）
ルールの見方すべてのルールを見て判断する番号の小さいルールから順に見て、最初に当てはまったものを使う
たとえ部屋ごとのドアの鍵建物の階の入口の警備

見分けるポイント

  • 「インスタンス単位」「ステートフル」「許可だけ」ならセキュリティグループ
  • 「サブネット単位」「ステートレス」「拒否のルールも書ける」ならネットワーク ACL
  • 特定の IP アドレスからの通信を「拒否」したいときは、拒否を書けるネットワーク ACL を使う
  • どちらも利用者が設定する。責任共有モデルでは「クラウドにおけるセキュリティ」（利用者の責任）

試験での出され方

「サブネットのレベルで動作するのはどれか」「ステートフルなのはどれか」のように、違いそのものを問う問題がよく出ます。「インスタンス＝セキュリティグループ」「サブネット＝ネットワーク ACL」の組を先に覚えましょう。

それぞれの用語

  • セキュリティグループ

    EC2 などに付ける仮想のファイアウォール。許可する通信だけを決める。行きの通信を許すと、戻りの通信も自動で許される（ステートフル）。

  • ネットワーク ACL

    サブネットの単位で付けるファイアウォール。許可と拒否の両方のルールを書け、行きと戻りの通信を別々に決める（ステートレス）。
