オンデマンドとリザーブドインスタンスとスポットインスタンスと Savings Plans の違い

EC2 の買い方の違いです。約束なしで使った分だけ払うのがオンデマンド、1年か3年の約束で安くするのがリザーブドインスタンスと Savings Plans、余っている EC2 を中断ありで安く使うのがスポットインスタンスです。

表で比べる

観点オンデマンドリザーブドインスタンス（RI）Savings Plansスポットインスタンス
約束なし1年か3年の利用を約束1年か3年、1時間あたりの利用額を約束なし
割引なし（基準の料金）大きく割引大きく割引とても大きく割引
中断されないされないされないAWS が必要になると中断されることがある
柔軟さいつでも始めて、いつでもやめられるインスタンスの種類などが決まる（コンバーティブルは変更できる）インスタンスの種類を変えても割引が当たる。Lambda や Fargate にも使える種類があるいつでも使えるとは限らない
向いている用途短い期間の仕事、急な仕事、使う量が読めないときずっと動かしておくシステムずっと使うが、構成を変えるかもしれないシステム止まってもやり直せる処理（バッチ処理など）

見分けるポイント

  • 「短期間」「予測できない」「中断されては困る」ならオンデマンド
  • 「1年か3年」「ずっと動かす」「安定した使用量」ならリザーブドインスタンスか Savings Plans
  • 「Lambda や Fargate にも割引」「インスタンスファミリーを変えても」なら Savings Plans
  • 「中断されてもよい」「いちばん安く」ならスポットインスタンス

試験での出され方

「中断されても問題のないバッチ処理を、最も安く動かすには」「1年間ずっと動かすサーバーの費用を下げるには」のように、使い方から買い方を選ぶ問題がよく出ます。「約束があるか」「中断されてもよいか」の2つで見分けましょう。

それぞれの用語

  • オンデマンドインスタンス

    前もって約束せず、使った時間の分だけ払う EC2 の買い方。急な仕事や、短い期間の利用に向く。

  • リザーブドインスタンス（RI）

    1年か3年の利用を約束することで、オンデマンドより大きく割引される EC2 などの買い方。ずっと動かしておくシステムに向く。

  • スポットインスタンス

    AWS の余っている EC2 を、大きな割引で使える買い方。AWS が必要になると中断されることがあるので、止まってもよい処理に向く。

  • Savings Plans

    1年か3年、1時間あたりの利用額を約束することで割引される料金のプラン。インスタンスのタイプを変えても当てはまり、Lambda や Fargate にも使える種類がある。
