リホストとリプラットフォームとリファクタリングの違い

クラウドへの移し方の違いです。リホストはそのまま移す、リプラットフォームは一部だけクラウド向けに変えて移す、リファクタリングはクラウドの機能を生かすように大きく作り直して移します。

表で比べる

観点リホストリプラットフォームリファクタリング
別の呼び方リフトアンドシフトリフト・ティンカー・アンド・シフトリアーキテクト
変える量ほとんど変えない一部だけ変える大きく作り直す
例オンプレミスのサーバーを、そのまま EC2 に移す自分で管理していたデータベースを Amazon RDS に移すアプリをサーバーレス（Lambda など）の作りに変える
手間と時間少ない・速いほどほど多い・時間がかかる
クラウドの良さまだ生かしきれない管理の手間が減るいちばん生かせる

見分けるポイント

  • 「変更を加えずに」「すばやく移行」「リフトアンドシフト」ならリホスト
  • 「マネージドサービスに置き換える」「大きな作り直しはしない」ならリプラットフォーム
  • 「クラウドネイティブ」「サーバーレスに作り直す」「アーキテクチャを変える」ならリファクタリング
  • 移行の戦略はほかに、再購入（SaaS に乗り換え）・保持（移さない）・廃止（やめる）・再配置（VMware の環境をまとめて移す）がある

試験での出され方

移行の戦略（7つの R）は、場面から選ぶ問題がよく出ます。「アプリのコードを変えずに、できるだけ早く移したい」ならリホスト、「データベースだけ RDS にしたい」ならリプラットフォームです。

それぞれの用語

  • リホスト

    今のシステムを、作りをほとんど変えずにクラウドのサーバーへ移す方法。「リフトアンドシフト」とも呼ぶ。

  • リプラットフォーム

    大きく作り直さずに、一部だけクラウド向けに変えて移す方法。例: 自分で管理していたデータベースを Amazon RDS に移す。

  • リファクタリング

    クラウドの機能を生かすように、アプリの作りを大きく作り直して移す方法。リアーキテクトとも呼ぶ。
